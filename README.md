# SkeduleParse

Микросервис на Rust, который:

1. **Воркер** (фоновая задача, срабатывает раз в `POLL_INTERVAL_SECS`):
   - открывает страницу публичной Nextcloud-ссылки (`SOURCE_URL`, например
     `https://cloud.mirea.ru/index.php/s/XXXXXXXX`);
   - находит ссылку кнопки **Download** (используется скрытое поле
     `#downloadURL`, которое Nextcloud всегда кладёт на такие страницы, с
     запасными вариантами на случай нестандартной темы оформления);
   - скачивает соответствующий `.xlsx`-файл с расписанием;
   - парсит его (распознавая повторяющиеся по неделям блоки с шапкой
     `№ / Наименование / Спикер / Дата проведения / Время / Формат / ...`)
     и строит из найденных занятий iCal-календарь (`.ics`);
   - результат кладётся в общее состояние, доступное HTTP-серверу.

2. **HTTP-эндпоинт** `GET /calendar.ics` (путь настраивается через
   `CALENDAR_PATH`) отдаёт последний сгенерированный календарь с
   `Content-Type: text/calendar`, пригодный для подписки в Google Calendar,
   Outlook, Apple Calendar и т.п. (просто укажите URL сервиса как
   "добавить календарь по ссылке").

   Также есть `GET /healthz` — отдаёт JSON со временем последней успешной
   генерации, числом событий и последней ошибкой (если была) — удобно для
   мониторинга.

Если источник данных временно недоступен или формат файла неожиданно
изменился, воркер пишет предупреждение в лог и **продолжает отдавать
последний успешно построенный календарь**, не падая и не отдавая пустой
ответ.

## Конфигурация (`.env`)

Скопируйте [`./.env.example`](./.env.example) в `.env` и поправьте под себя:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SOURCE_URL` | — (обязательна) | URL страницы публичной ссылки Nextcloud |
| `POLL_INTERVAL_SECS` | `300` | Период опроса источника, сек |
| `BIND_ADDR` | `0.0.0.0:8080` | Адрес, на котором слушает HTTP-сервер |
| `CALENDAR_PATH` | `/calendar.ics` | Путь, по которому отдаётся календарь |
| `TZ_OFFSET_HOURS` | `3` | Смещение UTC для дат/времени в таблице (3 = Москва) |
| `HTTP_TIMEOUT_SECS` | `30` | Таймаут исходящих HTTP-запросов |
| `CALENDAR_NAME` | `Расписание` | Отображаемое имя календаря в приложениях |
| `RUST_LOG` | `info` | Уровень логирования (`tracing_subscriber::EnvFilter`) |

## Локальный запуск

```bash
cargo run --release
```

и затем:

```bash
curl http://127.0.0.1:8080/calendar.ics
```

## Развёртывание на минимальном сервере (1 vCPU / 1 GB RAM / 5 GB диска)

Собирать на самом целевом сервере не нужно — образ собирается
многоступенчато (`Dockerfile`), итоговый контейнер — это только бинарник
на `debian:bookworm-slim`, без тулчейна сборки. Занимает он минимально, а
память сервиса в рантайме — единицы-десятки МБ.

```bash
cp .env.example .env
# отредактируйте .env (как минимум SOURCE_URL)

docker compose build
docker compose up -d
```

`docker-compose.yml` уже ограничивает контейнер `1 CPU` / `256 MB RAM` —
с запасом для такого сервиса, но так, чтобы оставить ресурсы системе и,
например, обратному прокси (nginx/caddy) перед сервисом, если вы
терминируете на нём TLS.

Проверить, что всё поднялось:

```bash
docker compose logs -f
curl http://<сервер>:8080/healthz
curl http://<сервер>:8080/calendar.ics
```

Подписка в календарных приложениях (Google Calendar → «Добавить календарь»
→ «По URL», Outlook → «Добавить календарь» → «Из интернета», Apple
Calendar → «Файл» → «Новая подписка на календарь») — укажите
`https://<ваш-домен-или-ip>:8080/calendar.ics` (рекомендуется повесить
сервис за обратным прокси с HTTPS, т.к. многие клиенты неохотно работают
с http-подписками или не обновляют их по расписанию).

### Сборка без docker-compose

```bash
docker build -t skedule-parse .
docker run -d --name skedule-parse \
  --restart unless-stopped \
  --env-file .env \
  -p 8080:8080 \
  --memory=256m --cpus=1 \
  skedule-parse
```

## Формат исходных страниц

Скрипт рассчитан на типовые страницы публичных ссылок Nextcloud (как в
примере `https://cloud.mirea.ru/index.php/s/fWbnJ6mFDMQEbD3`) и на
Excel-файлы с повторяющейся по неделям структурой:

- строка-заголовок недели (`"01 / Неделя 01 / 09–15 ноября 2026"`);
- строка с названиями колонок, где распознаются по ключевым словам (без
  привязки к конкретным буквам столбцов): "Дата", "Время", "Формат",
  "Спикер"/"Лектор", "Трансляц"/"Встреч" (ссылка на эфир), "Запис"
  (ссылка на запись), "Наименование"/"Образователь"/"Дисциплин"/"Курс"/"Модул"
  (название занятия);
- строки занятий; строка без названия занятия (ячейка пустая) трактуется
  как "в этот день занятий нет" и пропускается.

Если у другой программы акселератора/факультета шапка таблицы называется
иначе, подправьте ключевые слова в `src/xlsx.rs` (`detect_header`) — сам
парсер колонок полностью от них зависит и не завязан на номера столбцов.

## Структура проекта

```
src/
  config.rs    — чтение .env / переменных окружения
  fetch.rs     — скачивание страницы шары и поиск ссылки Download, скачивание xlsx
  xlsx.rs      — разбор расписания из Excel в Vec<ScheduleEvent>
  schedule.rs  — модель события + конвертация местного времени в UTC
  ical.rs      — сборка .ics из событий (со стабильными UID)
  state.rs     — общее состояние (последний сгенерированный календарь)
  worker.rs     — фоновый цикл обновления
  server.rs    — HTTP-эндпоинты (axum)
  main.rs      — точка входа, запуск воркера и сервера
```
